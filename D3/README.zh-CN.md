# B10 REV-D3 固件逆向

[English](README.md) | [简体中文](README.zh-CN.md)

本目录仅整理原始 REV-D3：恢复的代码与分析说明，以及按需查看机器码/位图的工具。这里的函数名称和伪代码由二进制分析恢复，**不是原厂 C 源码，也不代表全部功能已完成反编译**。

证据等级：**确定**指镜像字节、指令、实际调用链或资源对应关系可直接复核；**推断**指根据控制行为解释物理用途。寄存器计数不等于实测电流、光量、色温或回电秒数。

## 固件输入与分支

`main` 分支仅包含逆向源码、说明和查看工具，不包含 BIN / DFU 固件或开发构建输入。[REV1](https://github.com/Caimankekw/Profoto-B10-X-Firmware-RCE-Development/tree/REV1/D3/firmware) 和 [REV5](https://github.com/Caimankekw/Profoto-B10-X-Firmware-RCE-Development/tree/REV5/D3/firmware) 分支均在 `D3/firmware/` 附有同一份必要 D3 输入。

在 `main` 上运行工具前，可从任一开发分支取得输入。例如，在仓库根目录执行：

```powershell
git fetch origin REV1
git restore --source=origin/REV1 --worktree -- D3/firmware/B10_REV_D3.bin D3/firmware/B10_REV_D3.dfu
python -m pip install capstone==5.0.9 Pillow==11.3.0
```

开发分支已附输入，直接安装对应根目录的 `requirements.txt` 即可。原固件及其资源归原权利人所有。

## 型号与回电控制

**确定：同一份 D3 支持四个型号。** 主控先读 OTP 的 X 字段，再采 ADC 通道 10，要求五次分类一致。

| 主控型号码 | 型号 | 功率板基础型号 |
| --- | --- | --- |
| `0x8C` | B10 | `0x8C` |
| `0x8D` | B10 Plus | `0x8D` |
| `0x8F` | B10X Plus | `0x8D`，另有 X 标志 |
| `0x90` | B10X | `0x8C`，另有 X 标志 |

功率板上下文 `ctx=0x100003F8`：`+0x64` 为基础型号，`+0x89` 为 X 标志。主控 X 判断 M:`08004E08` → M:`0800C46C` 发送 `0x1031`；P:`080001F4` 接收并置 X 标志，然后重载温控表。

P:`08009148` 的普通回电参数如下，`p=ctx+0x28` 是热预算百分数：

```c
enhanced = (ctx.x == 1) && (ctx.ready_dim != 0 || ctx.light_on == 0);
// Plus: K/T/C = enhanced ? 310/380/20 : 273/343/20
// B10:  K/T/C = enhanced ? 230/300/20 : 210/280/20
// 未知型号回退: 50/280/180
TIM15_CCR1 = C;
TIM15_ARR = TIM15_CCR1 + (uint16_t)((K * p) / 100);
q = TIM2_CCR1;
if ((uint32_t)(q + T) > 71)
    TIM2_ARR = (uint32_t)(T - TIM2_CCR1);  // 原码再次读取 CCR1
else
    TIM2_ARR = 72;
```

`ready_dim` 是 READY SIGNAL 的 DIM 配置（P:`ctx+0x45`）；`light_on` 是造型灯开关（`+0x44`）。因此 X Plus 在造型灯开启且 DIM 关闭时，回退 `273/343/20`；造型灯关闭或 DIM 开启时才使用 `310/380/20`。

**确定：** TIM15=`0x40014000`，并非闪光事件用的 TIM16。TIM2/TIM15 都启用单脉冲及预装载，TIM2 更新中断 P:`0800920C` 还受 PA15 输入影响。上述无符号分支不能简化成 `max(72, T−CCR1)`，ARR 增大也不能称为“PWM 频率提高”。TIM2 `CCER=0x12` 中 CC1E 未使能；不能把 CCR1 读取解释成已经证实的电流捕获闭环。

**推断：** X 参数与造型灯的互斥关系是在协调共同供电负载。代码不能证明两代功率硬件完全相同，也不能由 K/T 比例直接换算实际回电提速。

### 高压、温控与电池

P:`080092D4` 最快约每 5 ms 服务一次；时基来自 72 MHz 配置及 SysTick `LOAD=71999`。ADC2 通道 4 的换算量为 `raw×3/4095×199.44444`，处理结果是 `0.1×本次换算值+0.9×上次原始换算值`，**不是递归 IIR**。

| 状态 | 已恢复行为 |
| --- | --- |
| 0 / 1 | 关闭回电输出并进入空闲 / 空闲 |
| 2 | 电池毫伏转换值需 `>11999`；高压 `<30` 用共用软启动，否则装入普通参数 |
| 4 | 主回电；高压 `>500` 停止并转 3；同时检查升压进展 |
| 3 | 保持；高压 `<499` 再起充 |
| 5 | 到达已存延时后转 2 |

状态名称是解释，数值及分支可直接复核。500/499 是软件换算门限，高度可信对应电容高压；它们不等于所有触发许可或 READY 判据。升压监控窗口为 `p<=1 ? 1000 : min(1000, floor(20000/p))` ms，超过窗口且增长不足 1 个软件电压单位时进入保护；这不是固定回电时间。

四路 NTC 换算为摄氏度，回电取四路允许比例的最小值。X 分支仅把温控槽 1（ADC1 通道 4）的降额起/终点 `65/75°C` 改为 `73/83°C`，停充门限 `80°C` 改为 `88°C`；相关表 P:`0800BE00`、`0800BE70`。其余通道仍能更早限流；物理测温点未知，不能把门限当作环境温度或整机额定耐温。

电池 ADC1 通道 2 使用 `raw×3/4095×6.17647` 及 `0.2新值+0.8旧滤波值`。`>18.0` 进入保护，`<12.0` 为欠压候选，恢复门限 `>12.1`；欠压还需稳定确认。回电状态 4 及退出后 512 ms 内不刷新电池 ADC，所以该路径并非回电期间实时电池压降监测。

## NORMAL / FREEZE 放电

主控配置 `0x200019A4+0x25` 经命令 `0x0016` 写入功率板 `ctx+0x38`：0 为 NORMAL，非零为 FREEZE。普通链为 **模式/有效能级 → ROM 配方 → 事件编译 → 执行器**；不是给每一档编写一套独立算法。

| 表 | Plus（含 X Plus） | 非 Plus | 记录格式 |
| --- | --- | --- | --- |
| NORMAL | P:`0800B410` | P:`0800B8C0` | 100×12 字节：首段 a、尾长 b、占空比码 d（第三字段按 u8 读） |
| FREEZE | P:`0800B0F0` | P:`0800B280` | 100×4 字节：截止时刻 T |

索引 `clamp(E,1,100)−1`；面板名义档位为 `E/10`，但运行能级可能先经电压等补偿，不能把面板刻度始终等同直接 ROM 下标。P:`080068D4` 在普通查表路径不读 X 标志，故两款 Plus 共用放电表。

```text
NORMAL：取 (a,b,d)，PWM宽度 floor(2357*d/256)
  b>0：action3 @ a 切 PWM；action5 @ a+b 结束；追加 action5 @ a+b+1
  b=0：action5 @ a 结束；追加 action5 @ a+1
FREEZE：取 T，尾长=0；沿同一事件编译器生成结束事件
```

编译器 P:`0800705C` 将每条事件写为 12 字节（action@+0、time@+4、width@+8）；两个数组为 `0x100002C8`（触发）和 `0x100002FC`（门控）。执行器 P:`08005EF4` 控制 PA8 GPIO/HRTIM。

TIM16 事件计数单位名义为 `7/72 µs≈0.097222 µs`，执行器轮询 `CNT>事件时刻` 后动作。HRTIM 周期 2357、比较起点 96、宽度最终钳位 2261，名义载频约 30.55 kHz。**a 不代表从点火开始计算的全部初始光脉冲：PA8 在 TIM16 启动前已置高，前面还有触发/相位条件。** 上述时刻均不是光学 t0.1。

例如 Plus 名义 5.0 的 NORMAL 配方为 `(341,4250,114)`，FREEZE 截止为 1152；9.7 起 NORMAL 尾长为零，10.0 两模式截止均为 64500。改变首段、PWM 尾长和宽度会改变电流时序；原表可解释为经标定的光量/光谱折中。**未发现目标 Kelvin 到波形的直接映射，也未建立光谱反馈闭环；仅凭这些整数无法算出实际色温。**

原诊断命令 `0x1008/0x1009/0x100A` 可设置首段/尾长/占空比并置覆盖标志 `0x100002A6`；接收端未钳位时间。切模式不清除覆盖，已证清除路径是功率板复位。它们不是普通用户的调色温接口。

## 存储、协议与 USB 更新

主控运行配置基址 `0x200019A4`；型号在 `+0x3C`、模式在 `+0x25`、DIM 在 `+0x31`、造型灯开关在 `+0x0C`。StorageTask 与出厂重置代码存在；这些 RAM 偏移不能直接当作 EEPROM 文件布局。OTP 存放身份相关信息，和用户配置不是同一存储。

主控→功率板已确认命令：`0x0012` 能级、`0x0016` 模式、`0x0018` DIM、`0x001F` 造型灯、`0x1031` X 初始化。功率板协议解析入口 P:`08000190`，主控发送入口 M:`0800AF38`。

原 Windows 更新器使用 dfu-util、USB `0483:DF11`，读取 OTP `0x1FFF7800:512` 与主控固件信息 `0x08000000:2048`，检查产品族后写入并读回校验。产品族 `0x8C` 不单独区分 Plus/X/非 Plus。主控 M:`0800B614` 使用内嵌地址 `0x0808B670` 和长度 `0xC610` 更新功率板；PC 校验主控成功不等于已经独立读回功率板。

## 按需查看机器码

按上文取得固件输入并安装依赖后，在仓库根目录运行：

```powershell
python D3/disassemble.py --output-dir local_disassembly
python D3/disassemble.py --image powerboard --start 0x08009148 --end 0x0800920C --output-dir charge_slice
```

脚本先核验原始 BIN 与内嵌功率板哈希，只在指定目录生成反汇编，不访问 USB。它是线性解码工具，**数据、字面量池也可能显示成指令**，不会自动恢复函数边界或原始 C 代码。主控输出跳过内嵌功率板，后者使用自己的正确加载地址输出；已有同名文件拒绝覆盖。仓库不预存全量反汇编、位图或逐档导出数据。
